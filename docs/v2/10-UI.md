# 10 · UI 设计（六面）

> 目标读者：前端实现者、验收者。前置阅读：[01-VISION.md](01-VISION.md) §2/§5、[02-ARCHITECTURE.md](02-ARCHITECTURE.md) §2/§3、[03-DATA-MODEL.md](03-DATA-MODEL.md)、[LIFE-ENGINE.md](LIFE-ENGINE.md) §5。
> 基线：Memoh v0.13.1 `apps/web`（Vue 3.5 + TS + Vite 8 + Tailwind 4 + `@memohai/ui`）。本文只定义与上游的差异；上游已有组件的内部用法不重复。

## 1. 目标与边界

- 这是**她的生活台**，不是 Bot 管理后台：没有"创建/切换角色"，没有租户、成员、市场。
- **六面封顶**：今天 / 她 / 记忆 / 工作台 / 世界 / 设置。任何新能力必须归入其中一面；需要第七面时先改本文档并评审。
- **复用优先**：聊天流、工具卡、文件树、终端、浏览器、桌面、模型/渠道表单、备份卡片全部复用 Memoh；只重写导航、首页与六面容器。
- **不是全知视角**：网页只呈现 public 与指向 owner 的 relationship 记忆；私密抽屉在 UI 与 API 层都不存在入口（§5.4）。
- 非目标：移动原生 App、多用户协作、应用市场、ACP/Codex/Claude Code 入口、可视化工作流编排。六面是 owner 控制台；联系人若通过 Web 聊天，走独立的极简会话页（08 §3），不加入六面导航。

## 2. 信息架构

### 2.1 六面

| 面 | 回答的问题 | 她/你能完成的事 | 默认路由 |
|---|---|---|---|
| **今天** | 她现在怎么样？在做什么？ | 看状态与一天、接上对话、暂停/继续她的活动、看她没回谁 | `/` |
| **她** | 她是谁？变成了谁？ | 改人设种子/traits、读 SELF、批准成长、配声音、看相册 | `/her` |
| **记忆** | 她记得什么？为什么记得？ | 检索时间线、翻人物卡、看 threads、审暂存与 Dream | `/memory` |
| **工作台** | 她的电脑里有什么？ | 文件/终端/浏览器/桌面、活动日志、产出物、快照 | `/workbench` |
| **世界** | 她怎么和外界联系？ | 渠道状态与配置、账号归属、联系人、社交、技能/MCP | `/world` |
| **设置** | 系统怎么运转？ | 模型与凭据、健康检查、预算、备份、部署信息、许可 | `/settings` |

### 2.2 首次运行（onboarding）

| 步 | 内容 | 必填 | 跳过后果 |
|---|---|---|---|
| 0 | 管理员账号（复用 `/auth/login`；owner 单账号，联系人另行邀请/绑定） | 是 | 无法进入 |
| 1 | 她是谁：名字、头像、时区、生日（可选） | 名字/时区 | 不可跳过 |
| 2 | 人设种子：bio、personality、traits（先调 6 个核心）、3 个兴趣 | bio/至少 1 兴趣 | 可先用默认种子，之后在"她"里改 |
| 3 | 模型：chat 必填；decision/growth/dream/vision/embedding/tts 可继承 chat | chat | 未配置时进入"未配置"只读态（§5.1） |
| 4 | 世界：QQ（SnowLuma）可选；Web 渠道自动启用 | 否 | 可在"世界"补；Today 提示"她还收不到 QQ" |
| 5 | 完成：跑一次健康检查，展示"她今天打算做什么" | — | — |

规则：进度写服务端（`littly_config` 的 `onboarding` 段），刷新可续；只能有一个 person；模型测试失败允许"先保存、后修复"，但**已配置且无效**时启动失败（01 §5.8）。首次成功标准：能聊天、Today 有状态、至少 1 条种子记忆。

### 2.3 全局布局

- **桌面 ≥1280**：左侧 232px 导航（她的头像/名字/状态点 + 六项 + 底部健康与设置）；顶部 48px 页头（标题、状态 chip、⌘K）；内容区独立滚动。
- **平板 768–1279**：左栏收为 64px 图标（hover 显示标签）；Today 双栏变单栏，聊天用 sheet。
- **手机 <768**：顶部 44px（返回、标题、状态点、头像菜单）；底部 5 个主入口（今天/她/记忆/工作台/世界），设置放入头像菜单；`env(safe-area-inset-bottom)`。
- **状态 chip**：`醒着 / 在忙：<活动> / 睡觉 / 暂停`，点击跳到 Today 活动卡；颜色之外必须有文字。

## 4. 六面详设

### 4.1 今天（`/`）

桌面 12 栅格：左 7 概览，右 5 聊天；手机分段"概览 / 对话"。

| 模块 | 内容 | 复用/新增 |
|---|---|---|
| 状态卡 | energy/mood/socialNeed/satiety 四 bars；attention 文案；上次 tick；当前活动 | 新 `StateCard`；`progress`/`tooltip` |
| 今日意向 | 主意图 + 2–3 个候选活动 + 为什么（引用兴趣/thread） | 新 `IntentionsCard` |
| 她正在做什么 | 活动标题/kind/进度/已用预算；暂停/继续/取消；日志入口 | 新 `CurrentActivityCard` |
| 待续活动 | paused/planned 列表；排序按 next_step/到期 | 新 `PendingActivities` |
| 今天的时间线 | wake/message/reply/activity/post/dream/sleep 事件；按上午/下午/晚上分组 | 新 `DayTimeline`；`scroll-area` |
| 会话 | Web 会话、未读；其他渠道只在"没回"里显示决策摘要，不显示正文 | 复用 `panel-sessions`/`session-item` |
| 聊天 | Web 渠道流式消息、工具卡、附件、审批卡；发送/重试 | 复用 `chat-pane`、`message-item`、`tool-call-block`、`attachment-block` |
| 主动消息 | 今天她主动发的；outbox 状态 draft/queued/sending/sent/failed/unknown/cancelled/expired + 原因；需审批时显示待批（走上游审批） | 新 `ProactiveList` |
| 没回的消息 | 仅列 no_reply/later/defer/explain_later；原因摘要；"她后来提起了吗" | 新 `ReplyDecisionList` |
| 日记预览 | 今天是否写了日记；仅 public/展示摘录时显示内容，否则只显示"私有"与字数 | `markdown-preview` |

交互：状态卡点击弹"状态详情"（四维变化原因，来自 `state_events`）；活动卡按钮按 §5.2；聊天走 Web 渠道（`POST /api/chat` + WS/SSE，08 §3），失败显示重试而不是假消息；`?session=` 深链恢复会话。空态：首次运行显示"她还不知道今天做什么"→ 引导去 onboarding/让她生成今日意向；睡眠态降低动效并显示"她睡了，除非紧急她不会回"。

### 4.2 她（`/her`）

| Tab | 内容 | 复用/新增 |
|---|---|---|
| 人设 | 头像、昵称、时区、生日、bio、personality、scenario；保存校验 | 复用 `form`/`field`/`textarea`/`avatar`；新 `PersonaForm` |
| SELF | `SELF.md` 编辑 + 预览切换；显示最近修改者（你/Dream）；乐观锁 | `monaco-editor` + `preview-mode-toggle` + `markdown-preview` |
| Traits | 9 维滑杆（0–100）；每维一句"影响什么"；与种子差异高亮；重置 | `slider`；新 `TraitEditor` |
| 成长 | 待批提案（before→after diff、理由、来源）；批准/拒绝；历史 | 新 `GrowthProposals`；`diff-title-bar` |
| 声音 | TTS provider/model/音色；试听文本；不可用时禁用并说明 | 复用 voice 页的 `provider-setting`/`model-config-editor` |
| 相册 | public 图片 artifact 网格；lightbox；来源活动；caption | `media-gallery-lightbox`；新 `AlbumGrid` |

约束：人设是**种子**不是每句话模板（页面文案写明）；traits 可手改（种子校准，audit 标记为人工）；延续性变化走成长提案，不允许手改后假装"她长大了"；相册只展示 artifact，不扫描私密 vault。

### 4.3 记忆（`/memory`）

顶部检索条：关键词、domain、kind、时间范围、人物、可见性（公开/与我相关）；结果计数与耗时；默认最近 30 天时间线。

| 模块 | 内容 | 复用/新增 |
|---|---|---|
| 时间线 | 按天分组；卡片含标题/摘要/时间/重要度/情绪/人物/来源/可见性 | 新 `MemoryTimeline`；`badge` |
| 详情 | 正文 Markdown、vault path+line（可复制）、thread/artifact 链接、涉及人物；只读 | `sheet` + `markdown-preview`；新 `MemoryDetail` |
| 人物卡 | **分层**：important/friend/intimate 显示完整卡；extended important 显示 summary 模式；acquaintance 只显示 brief 一行（聚合视图）；stranger 不显示卡片；不展示她与第三人的私密细节 | `persona-tile`；新 `PersonCard`/`PeopleTierList` |
| 回收站 | archived 人物：搜索姓名/别名/事件、查看一行印象、手动恢复（需确认身份）；owner only | 新 `ArchiveList` |
| Threads | open/waiting/resolved 三列；next_step、due、相关人；按关联记忆可见性过滤；可改状态 | 新 `ThreadsBoard` |
| 暂存 | 待处理候选：原文摘录、建议 domain/visibility、来源；保留/丢弃/批量 | 新 `StagingList` |
| Dream | 报告列表（状态、耗时、抽取/合并/更新数）；详情仅统计/失败原因/重试，不展示私密正文 | 新 `DreamReports` |

**可见性口径**：owner_web 只返回 `public` 与 `relationship(owner_id)`（05 §5.1）；其他 relationship 与 private 都不返回。页面没有"私密"筛选/tab/计数/搜索提示；v1 只读；服务端保留编辑走 supersede 的能力（05 §3.5）。"她主动展示"不是第四种可见性，而是她在对话里主动引用 artifact/摘录（03 §3.5；可选 Display token，05 §8）。

### 4.4 工作台（`/workbench`）

顶部运行条：runtime（docker/apple/containerd/local）、状态、CPU/内存、启动/停止、按需启动开关、磁盘余量；桌面不可用时显示原因而非假装可用。

| 面板 | 内容 | 复用/新增 |
|---|---|---|
| 文件 | 树 + Monaco 编辑器 + Markdown/图片/HTML 预览；新建/上传/重命名/删除（确认）；未保存拦截 | `file-tree`、`file-viewer`、`monaco-editor`、`markdown-preview`、`html-preview` |
| 终端 | xterm 多 tab、复制、清屏、终止；断线重连；真实命令提示 | `terminal-pane`、`dockview/terminal-tab` |
| 浏览器 | 会话启停、地址栏、截图、同源代理；显示"她也在用" | `browser-pane`、`dockview/panel-browser` |
| 桌面 | WebRTC/noVNC 画面、键鼠、全屏；不支持时给启用容器/换 runtime 的指引 | `display-pane`、`dockview/panel-display` |
| 活动 | 当前/最近活动、进度、暂停/继续、日志时间线；工具调用详情 | `tool-call-detail-*`；新 `ActivityLog` |
| 产出 | public artifact 网格/列表、预览、来源活动、下载、在文件中打开 | 新 `ArtifactGallery` |
| 快照 | 列表（时间/来源/大小）、创建、回滚（二次确认、说明影响） | 新 `SnapshotList` |

并发保护：她正在使用某面板时，顶部显示"她正在使用终端/浏览器"，默认把你切到只读观察，可点"接管"（会记录 audit，并可能打断她的活动）；停止工作台前若有 running 活动，先确认。

## 5. 关键交互与状态

### 5.1 全局状态矩阵

| 状态 | 触发 | UI | 可做 |
|---|---|---|---|
| 首次加载 | 冷启动 | 骨架屏（导航+卡片轮廓） | 等待 |
| 未配置 | 无 chat 模型/无 person | 全页引导卡 + 允许去设置；聊天禁用 | 配置、看只读记忆 |
| 模型异常 | health=fail/degraded | 顶部红条或黄条（用途+错误摘要+去设置）；聊天输入禁用；活动自动暂停 | 修复、看历史 |
| 渠道断开/等待 | status=error/disconnected/starting/waiting_scan | 世界卡片红点或进度；Today 黄条；waiting_scan 给 noVNC 扫码入口；web 聊天不受影响 | 重连、扫码、测试、看日志 |
| 工作台不可用 | stopped/starting/error/按需未启动 | 空态/进度/错误 + 启动或重试；需要工具的活动排队不失败 | 启动、重试、看日志 |
| 刹车中 | brake 开启 | 顶部常驻条；外发/活动按钮禁用 | 解除、查看原因 |
| SSE 断线 | 网络/服务重启 | 顶部"实时更新已断开"，15s 轮询兜底 | 继续浏览 |

错误分级：401→登录；403→权限说明；404→空态（记忆私密也用 404）；409→冲突面板（渠道/账号/快照）；422→表单内联；5xx→可重试 + 请求 id。

### 5.2 活动生命周期

| 状态 | 按钮 | 说明 |
|---|---|---|
| planned | 开始（她可自主，也可手动触发）、取消 | 到点由 tick 启动；手动启动要确认 |
| running | 暂停、取消、看日志 | 暂停保存进度；取消需二次确认 |
| paused | 继续、取消 | 继续从 checkpoint 而不是重来 |
| done | 看产出/日志 | 不提供"重跑"假动作，可新建 |
| failed | 重试（新活动）、看错误 | 明确失败原因；不显示假进度 |
| cancelled | 看日志 | 不可恢复 |

任何"暂停/取消"都写 `activity_logs` 与 audit；UI 不伪造进度条（进度来自服务端 `progress`，未知时显示不确定态）。

### 5.3 回复决策留痕

Today 只列"没回/晚回/延迟决策/稍后解释"，避免把每次秒回都做成噪声；只显示元数据，不展示其他渠道正文。每条显示：谁、哪个渠道、收到时间、动作徽标（`immediate`/`short`/`later`/`no_reply`/`explain_later`/`defer`，中文标签由前端映射）、原因摘要（忙/状态/关系/内容/边界/积压/系统保底）、她是否已再次提起。原因来自 `littly_reply_decisions.factors` 的结构化字段，**不展示原始提示词或思维链**。系统异常单独标"服务错误（不是她不想回）"，与 `no_reply` 严格区分。

### 5.4 私密抽屉的"UI 不存在"实现

1. 服务端 DTO 不包含 private 字段；按 id 查询 private/他人 relationship 返回 **404**，不返回 403（不泄露存在性）。
2. 所有列表/搜索/计数/导出在 SQL 层用 owner_web 谓词（public 或 relationship(owner_id)）；前端不提供"显示私密"开关。
3. 没有 `/memory/private` 路由、没有导航项、没有空态提示；命令面板不注册相关命令。
4. 前端不请求、不缓存、不写 localStorage；不把私密内容塞进隐藏 DOM；日志/audit 不记录正文，只记录操作类型与 id。
5. 页面文案明确："私密内容只在她服务器的 vault 文件里，这个网页没有入口。" 展示是她主动在对话里引用 artifact/摘录（03 §3.5；05 §8 的 Display token 只做对话内一次性只读），不改 visibility、不进列表/搜索。

### 5.5 实时更新

- `GET /api/events`（SSE）：`activity.updated`、`state.updated`、`message.created`、`reply.decided`、`channel.updated`、`health.updated`、`memory.created`、`dream.finished`；带单调 `seq`。
- 前端按事件失效对应 query（`@pinia/colada`），不整页刷新；聊天消息按 session 增量合并。
- 断线指数退避（1s→30s），恢复后带 `since=seq` 补拉；SSE 不可用降级 15s 轮询。
- 回复决策、活动状态**不做乐观更新**，以服务端为准。

## 7. 设计约束

- **技术栈**：Vue 3.5 + `<script setup>` + TS strict；Pinia + `@pinia/colada`（上游已有）；Tailwind 4；组件只从 `@memohai/ui` 与 `apps/web/src/components` 取，不引第二套 UI 框架。
- **目录**：`pages/<face>/`、`components/<domain>/`、`lib/api/<domain>.ts`；页面不直接 `fetch`，统一走 API client。
- **响应式**：至少测 390×844、768×1024、1440×900；触控目标 ≥44px；表格在手机转卡片。
- **Safari/iOS**：用 `100dvh` + fallback；尊重 safe-area；避免依赖 hover 的关键操作；WebRTC 桌面在 iOS 明确不可用；`backdrop-filter` 只做装饰。
- **无障碍**：每面一个 `h1`、地标、焦点环、Esc 关闭浮层、`aria-live` 播报异步结果、`prefers-reduced-motion`、颜色不作为唯一状态信号、对比度 ≥4.5:1。
- **性能**：Today 首屏只打 `/api/today` + `/api/bootstrap`；Monaco/xterm/dockview/显示面板按路由懒加载；长列表虚拟滚动（>200 条）；图片懒加载。
- **安全**：密钥永不回显；私密内容永不请求；外链 `rel="noopener"`；noVNC 同源改写；错误信息不回显 token。
- **六面规则**：新功能没有归属就不做；临时实验放 `/dev/components` 或开关后隐藏，不得新增导航项。

## 8. 验收（每面可做什么）

- **今天**：能看到四维状态、当前活动与进度；能暂停/继续/取消；能看到今天时间线、会话、主动消息、没回的消息与原因、日记状态/可展示摘录；能发消息并收到流式回复；刷新/深链后状态不丢。
- **她**：能改人设与 traits 并保存；能编辑 SELF 并预览/解决冲突；能批准/拒绝成长提案；能试听声音；能看相册来源。
- **记忆**：能按关键词/domain/人物/时间检索；能看到 vault 出处；能看人物卡与 threads；能处理暂存；能看 Dream 报告；搜索"私密"无结果，他人关系记忆也不出现。
- **工作台**：能启动/停止工作台；能浏览/编辑/保存文件；能开终端执行命令；能开浏览器；桌面不可用时有明确说明；能看活动日志与产出；能创建/回滚快照（有确认）。
- **世界**：能看到渠道状态与账号归属；能配置并测试 QQ；能扫码登录；能管理联系人身份映射；能配置社交与技能/MCP；账号冲突时有明确阻断。
- **设置**：能按用途配模型并测试；能跑健康检查并看到每项结果；能设预算；能导出备份；能看部署信息与许可；能一键刹车并恢复。
