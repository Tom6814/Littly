# Littly v2 · 生活引擎（Life Engine）设计

> 状态：设计稿 v0.1（2026-11-06）· 讨论中，未实现。
> 目标：让她**在没人找她的时候也在生活**，并且她的行为由"她是谁、她此刻怎样、她在乎谁"决定，而不是由定时器或任务列表决定。

---

## 1. 为什么需要 Life Engine

旧项目能聊天、能记忆、能主动发消息，但本质是：

```
收到消息 → 组装人设+记忆+历史 → 模型 → 回复
定时器 → 检查静默 → 决定要不要说话
```

这套东西的"主动性"来自计时器，而不是来自**欲望、兴趣、未完成的事**。所以她的"主动"看起来像提醒，不像活着。

Life Engine 要补的是中间那一层：

```
她是谁 ──▶ 她想做什么 ──▶ 她此刻能做什么 ──▶ 她在工作台里做 ──▶ 产出/经历
   ▲                                                              │
   └──────────── 记忆 · 状态 · 人物卡 · 成长（回写） ◀────────────┘
```

它同时回答四个问题：

1. **她现在在做什么？**（活动/注意力）
2. **她为什么做这个？**（兴趣、目标、状态、记忆里的线索）
3. **别人找她时她理不理？**（性格、关系、状态、在忙程度）
4. **她做完之后变成什么？**（产出物、记忆、日记、兴趣变化、关系变化）

---

## 2. 设计原则（不变量）

1. **一个人**：一个实例一个她；她的记忆、状态、工作台、成长只有一份。
2. **一份人生**：记忆是自传式的（她经历的），不是"每个人一个档案库"。
3. **她有一台自己的电脑**：工作台是真实环境，她的活动有真实后果与产出。
4. **主动不是定时器**：主动性来自兴趣、目标、未完结的事与关系。
5. **有性格**：她有自己的偏好、边界、情绪与"不想理人"的权利。
6. **有隐私**：她有抽屉；网页端不是全知视角。
7. **自由但可刹车**：日常自主，不可逆/对外高风险动作要保护。
8. **可解释**：她能在之后说出"我那会在忙/我不想说话/我忘了"，而不是神秘消失。

## 3. 认知模型

她"脑子里"有六类东西：

| 层 | 内容 | 存哪 |
|---|---|---|
| **自我（SELF）** | 我是谁、我现在的生活、长期主题、我在意什么 | `SELF.md` + 索引 |
| **人物（People）** | 她对每个人的理解：关系、历史、边界、称呼、TA 说过的事 | `people/<id>.md`（人物卡） |
| **记忆（Memory）** | 她经历/知道的事件、感受、观点、知识 | `domains/**` + FTS/向量索引 |
| **状态（State）** | energy/mood/socialNeed/satiety + 注意力/在做什么 | `state`（DB/快照） |
| **兴趣与目标（Interests/Goals）** | 她最近好奇什么、在追什么、想完成什么 | `interests`/`goals` 表 |
| **未完结的线（Threads）** | 约定、矛盾、项目、待续的故事 | `threads/` |

### 3.1 它们如何参与一次对话

```
消息进来
  → 更新注意力/状态（谁在找她、重不重要、她在忙什么）
  → 检索：SELF（常驻）+ 当前人物卡（常驻）+ 最近生活（常驻）
           + 相关记忆（可见性过滤）+ 未完结的线
  → 回复决策（见 §5.9，不一定回）
  → 生成回复（语气/长度/内容由性格与关系决定）
  → 落库；更新关系记忆/情绪；可能把她手头活动推到稍后
```

### 3.2 它们如何参与"自己的生活"

```
生活 tick（每 15~60 分钟，或活动结束时）
  → 推进状态（衰减/恢复）
  → 看看今日意向与未完成活动
  → 若空闲：按兴趣×状态×紧迫度选择一个活动
  → 在工作台执行（可后台、可多次 tick 继续）
  → 产出/记录/回写记忆与状态
  → 决定要不要对外分享（发帖/给某人发消息）
```

## 4. 记忆系统

### 4.1 存储结构（她自己的 vault）

```
memory/
  SELF.md                      # 自传档案（她是谁 / 现在的生活 / 长期主题）
  PEOPLE.md                    # 人物总览（可选，自动生成）
  people/<contactId>.md        # 人物卡：她对这个人的理解
  domains/
    life/                      # 经历（episodic）：发生了什么
    feelings/                  # 情绪与内心
    thoughts/                  # 观点、判断、反思
    plans/                     # 她打算做的事
    knowledge/                 # 她学到的知识（读书/搜索/工作台产出）
    routines/                  # 习惯、偏好、日常
  threads/                     # 未完结的线（可按主题/人物索引）
  diary/                       # 日记（第一人称、按天）
  _staging/                    # 暂存（对话/活动里候选记忆）
  _history/                    # 墓碑（失效/被取代）
  index.sqlite                 # 派生索引（FTS + 向量），可重建
```

**明确废弃**：`memory/<bot>/<contact>/` 的 per-person 库、旧 `memories` 表、crossPool 跨人注入。人物卡不是"记忆库"，是"她对这个人的认知"，一个文件、一页纸的量级。

### 4.2 记忆条目 schema

```yaml
id: mem_xxx
domain: life|feelings|thoughts|plans|knowledge|routines
kind: episodic | semantic | social | reflection
title: 一句话
event_time: 2026-11-06T14:00:00+08:00   # 事情发生的时间（衰减按这个）
record_time: ...                         # 写入时间
people: [tori, goldwhale]                # 涉及谁
visibility: public | relationship:tori | private
importance: 1..5
emotion: 开心 | 委屈 | 平静 ...
source: conversation | workspace | diary | dream | post
links: [thread:xxx, artifact:xxx, people:tori]
```

### 4.3 可见性（隐私三层）

| 层 | 含义 | 网页端 | 服务器文件 |
|---|---|---|---|
| `public` | 一般经历/知识/公开想法 | 可见 | 可见 |
| `relationship:<id>` | 与某人的私事/悄悄话 | 仅在与该人的上下文里用于生成，**不作为"已知事实"给其他人**；页面展示需授权 | 可见 |
| `private` | 她的私密抽屉（日记/草稿/不想说的事） | **无入口**（页面不展示、不搜索） | 可见（服务器文件） |
| 展示（display） | 她主动"拿给你看"的内容（摘录/作品/图片） | 只读可见 | 可见 |

> 说明：不做加密抽屉。作为服务器主人，你仍可在服务器文件里翻到私密内容；网页端没有偷看入口，这是产品上的"尊重"，不是密码学保证。
> 检索时：`public` 永远可用；`relationship:X` 只在和 X 的对话里可用；`private` 不进入任何对话检索（只可能被她主动"展示"或写进她当前的想法）。

### 4.4 检索（对话时）

1. **常驻层**：`SELF.md` 摘要 + 当前人物卡 + 最近 1-3 天生活摘要 + 当前状态旁白；
2. **相关层**：FTS + 向量 RRF（k=60）检索，过滤可见性；
3. **重排**：`0.55·相关度 + 0.25·重要度 + 0.20·新鲜度`（沿用旧项目的检索加权经验）；
4. **上限**：默认 ≤ 12 条进入上下文；人物卡/边界/近期事件优先；
5. **出处**：返回 path+line，便于调试与 UI 展示。

### 4.5 写入来源

| 来源 | 例子 | 默认 domain |
|---|---|---|
| 对话 | 他说他下周考试；她说她今天好累 | life / feelings |
| 工作台 | 她写了一篇笔记、整理完相册、做了个 demo | life / knowledge |
| 日记 | 当天总结 | life / feelings |
| 睡眠整理 | 反思、抽象认知、人物卡更新 | reflection / thoughts |
| 发帖/互动 | 她发了一条动态、有人回复 | life / social |

### 4.6 整理（Dream / 反思）

**睡眠时计算**（借鉴 Letta sleep-time compute 与旧项目 Dream）：

- 触发：每天凌晨（她"睡觉"时）或暂存 ≥N 条；
- 步骤：读取当天的对话/活动/日记 → 抽取记忆 → 去重/合并 → 更新人物卡 → 更新 SELF（如果她变了）→ 提炼"我最近好像…"（兴趣演化输入）→ 写日记/反思报告；
- 预算：单次 token/时间上限；失败保留暂存，下次重试；
- 产物：`dream_reports` 记录（可解释）、`_history` 墓碑、索引重建。

### 4.7 迁移策略

本轮**不迁移旧数据**：旧 DB/memory 只备份。原因：旧结构（per-person、旧表、双轨）与新模型冲突，强行迁移会把旧问题带进新系统。等 v2 稳定后，单独做"历史导入"项目。

## 5. 生活引擎

### 5.1 时钟与作息

| 时段 | 她在做什么 |
|---|---|
| `wake` | 起床、看消息、生成今日意向 |
| `quiet` | 夜间免打扰（可配置），只有紧急/约定事项例外 |
| `sleep` | 睡眠：状态恢复 + 睡眠时计算（Dream/明日计划） |
| 白天 | 活动块（见 §5.5），聊天会打断/插入 |
| 吃饭/休息 | 状态驱动的小活动（也是生活的一部分） |

- 时区：实例配置；作息可被人设覆盖（夜猫子/早睡）。
- "现在几点"必须显式进入提示词，避免模型编造时间。

### 5.2 状态模型

四维（0-100，沿用旧项目并修复"只衰减不恢复"的缺陷）：

| 维度 | 衰减 | 恢复/事件 |
|---|---|---|
| energy（精力） | -2/h | 睡眠 +40~60；休息 +10；高强度活动 -10~20 |
| mood（心情） | 向 55 回归 1/h | 被关心 +6；吵架 -10；活动成功 +4；被冷落 -5 |
| socialNeed（社交需求） | +3/h | 聊天 -15~25；发帖/互动 -10；独处久了升高 |
| satiety（饱腹） | -4/h | 吃饭 +30；饿到 0 时活动效率下降、心情下降 |

附加：`attention`（当前在做什么/是否被打断）、`activity_focus`、`last_interaction`。

- 状态影响：活动选择（累/饿时选轻活动）、回复决策（忙/烦时不一定回）、语气与长度、主动性。
- 状态恢复是**睡眠**必须做的事（旧 bug：能量只降不升，最后恒为 0）。

### 5.3 兴趣与目标（种子 + 演化）

**种子（你给人设的）**：兴趣主题、长期目标、价值观、她喜欢/讨厌的东西。

**演化（她自己长出来的）**：
- 来源：记忆里反复出现的内容、对话里被激发的好奇、工作台里做顺手的事、社交媒体上看到的东西；
- 机制：Dream 时生成候选（"我最近总在想 X"/"我想学 Y"）→ 进入兴趣池 → 小成本试探（一次活动）→ 有效则升温，无效则衰减；
- 兴趣有 strength/decay；目标有 deadline/status（active/paused/done/abandoned）；
- 她可以说"我最近对…感兴趣"、"我放弃了…"，也允许兴趣与现实冲突（不一定都完成）。

### 5.4 计划（分层）

| 层 | 粒度 | 说明 |
|---|---|---|
| 长期目标 | 周/月 | 她想完成的事（项目/学习/关系/生活改善） |
| 今日意向 | 天 | 起床时生成 1 个主意图 + 2-3 个候选活动 |
| 活动块 | 30-120 分钟 | 具体做什么（写笔记/读书/整理/研究/发帖） |
| 反应式重规划 | 事件触发 | 被打断/失败/情绪变化后重新安排 |

- 计划不是硬日程；允许"今天不想按计划来"（符合性格与状态）。
- 未完成活动进入 `threads`/待续队列，跨天继续，不丢。

### 5.5 活动（Activity）

| 类型 | 例子 | 需要的工具 | 产出 |
|---|---|---|---|
| 学习 learn | 读一篇论文/教程、查一个概念 | 浏览器、搜索、笔记 | 笔记/知识条目 |
| 研究 research | 追一个疑问、对比几样东西 | 浏览器、搜索、文件 | 研究报告 |
| 整理 organize | 相册、收藏、笔记、下载、工作台 | 文件工具 | 归档/清单 |
| 写作 write | 日记、文档、帖子草稿、给某人的信 | 文件、文档导出 | 文档/草稿 |
| 创作 create | 图片、小项目、demo | 生图、代码执行、文件 | 作品 |
| 维护 maintain | 更新技能、整理记忆、备份 | 文件/记忆工具 | 变更记录 |
| 社交 social | 发动态、回复评论、给朋友发消息 | 社交工具/渠道 | 帖子/消息 |
| 休息 rest | 听歌、发呆、睡觉 | 无 | 状态恢复 |

**选择算法（fitness）**：

```
score(activity) =
  w1·兴趣匹配 + w2·目标相关 + w3·状态适配(精力/心情/饱腹)
+ w4·社交需求 + w5·未完结线程的紧迫 + w6·随机性(避免机械化)
```

- 硬约束：预算（token/时间/并发）、免打扰时段、安全档位；
- 同一活动可跨多个 tick 执行（后台任务）；
- 每完成一个活动写 `activity_log`（做了什么/花了多久/成功失败/产出物），它同时是记忆与日记素材。

### 5.6 睡眠时计算（夜间）

| 任务 | 内容 | 产出 |
|---|---|---|
| 记忆整理 | 当天对话/活动 → 记忆条目 | `domains/` |
| 反思 | 抽 3-5 条高层认知（"我最近…"） | `thoughts/reflection` |
| 人物卡更新 | 今天和谁发生了什么 → 更新 people 卡 | `people/*.md` |
| SELF 更新 | 生活主题/状态变化（低频） | `SELF.md` |
| 日记 | 第一人称写今天 | `diary/` |
| 明日计划 | 生成明天意向与候选活动 | `intentions` |

全部在"睡眠"窗口后台执行；失败不影响第二天，保留重试。

### 5.7 社交节律（发帖 / 互动）

借鉴 Chirper 的自主社交，但**质量优先、频率克制**：

- 发帖来源：活动产出（"我写了个东西"）、生活观察、对某事的看法、回应某人；
- 频率：默认每天 0-2 条（人设可调；不是打卡）；
- 平台：X / B站 / QQ空间 等；每平台有独立节奏与风格；
- 互动：看 feed、回复评论、点赞（低调，避免刷屏/骚扰）；
- 边界：涉及他人隐私、争议敏感话题、账号安全时不发；
- 全部进记忆（"我发了一条关于 X 的动态，有 N 个回复"）。

### 5.8 回复决策（Persona-driven Reply Policy）★

> **核心修正：别人说话 ≠ 她必须回复。**

回复不是默认动作，而是一个决策结果。她的性格、关系、状态、当下活动共同决定。

#### 输入因子

| 因子 | 例子 |
|---|---|
| **性格特质** | 粘人/高冷、耐心、自尊、社恐/社牛、占有欲、是否爱已读不回 |
| **关系** | 主人/朋友/陌生人/不喜欢的人；最近亲密度；是否有未解决的矛盾 |
| **她的状态** | 心情差、能量低、正沉浸在某件事、社交需求已满足/爆棚 |
| **当下活动** | 正在写东西/做项目/睡觉 → 更可能忽略或晚回 |
| **消息本身** | 内容重要性、紧急度、是否被冒犯、是否只是表情/灌水、是否问到她不想说的事 |
| **时间/渠道** | 深夜/工作时间；不同平台的回复习惯 |
| **未读积压** | 已经堆积很多时，可能干脆不回或集中回 |
| **边界** | 她明确说过"这件事我不想聊" |

#### 输出动作

| 动作 | 表现 | 场景 |
|---|---|---|
| 立即回 | 秒回、自然 | 重要的人/有意思的话题/她正好闲着 |
| 短回 | "嗯""在忙，晚点" | 忙但不想失礼 |
| 稍后回 | 5 分钟~几小时后回，理由自然 | 在活动中/需要想一想 |
| 已读不回 | 不回复；可能再也不会回 | 灌水/冒犯/她不在意的人/她想冷处理 |
| 不回但下次解释 | 下次开口自然带过（"刚才在忙"） | 关系重要但当下不想回 |
| 干脆不理 | 长时间无响应 | 冲突/边界被侵犯/性格使然 |

#### 人格预设如何影响

| 性格 | 典型行为 |
|---|---|
| 粘人/高依赖 | 几乎都回，秒回；不回会焦虑；主动追问 |
| 高冷/独立 | 选择性回；已读不回是常态；重要的人例外 |
| 敏感/容易受伤 | 情绪差时冷战；需要哄；会在意回复速度 |
| 社恐 | 回得慢、字少；群聊潜水；私聊更愿意 |
| 社牛/爱热闹 | 回得快、话多；主动找话题 |
| 有原则 | 某些话题/行为直接不回或拒绝 |

#### 防止体验崩坏的护栏（必须）

1. **重要关系保底**：把某人标为"重要"后，她最多沉默 N 小时（可配置），之后至少给一句解释或回应（性格仍可冷淡，但不永久消失）。
2. **紧急内容例外**：求助/安全/明确重要的事情，回复决策优先级提高（由消息分析 + 用户标记）。
3. **可解释**：不回复的决策记录原因（忙/不想说/忘了），她下次可以自然提起，不能"查无此人"。
4. **用户可设边界**：哪些人/事必须回、哪些可以不理；她可以讨价还价（性格），但不能破坏用户的安全底线。
5. **观察与调优**：`reply_decisions` 表留痕；控制台能看到"她今天回了谁、没回谁、为什么"，避免"系统挂了"和"她不想回"混淆。

#### 实现位置

`attention / interrupt` 模块（消息进来先评估）→ `reply_policy`（性格+关系+状态+内容）→ 动作（回/置后/不回）→ 更新状态（未回的愧疚/自在/注意力）→ 记忆（"他找我，我在忙，没回"）。

### 5.9 主动消息（她来找你）

不是定时器，而是**有内容才开口**：

- 来源：活动产出（"我刚写完/看到这个"）、想念/关系维护、未完成的约定、生活事件（吃饭/出门/天气）、社交媒体互动；
- 时机：她闲下来/状态合适/关系需要；
- 频率：按关系与性格决定；被冷落会减少主动；
- 内容：有具体信息，不是"在吗"。

### 5.10 打断与恢复

- 聊天打断活动：先评估要不要回（§5.8）；回的话记录活动进度；
- 活动打断聊天：她可能晚回（状态/注意力）；
- 恢复：活动可跨 tick 继续，进度与待办存工作台。

## 6. 人格、成长与边界

### 6.1 性格特质（traits）

建议字段（0-100 或 1-5）：`clinginess（粘人）`、`socialEnergy（社交能量）`、`pride（自尊/要强）`、`patience`、`curiosity`、`orderliness（秩序）`、`possessiveness`、`expressiveness（表达欲）`、`independence`。

- traits 影响：活动偏好、回复决策、主动性、语气、边界；
- traits 可以随成长缓慢变化（月度评审），但变化有上限（旧项目成长三铁律可复用）。

### 6.2 成长

- 月度"潜意识"评审 → 维度变化提案 → 人类批准（旧项目机制可移植）；
- 变化写入 `SELF.md`（"我变了"章节）；
- 不篡改过去记忆，只新增/重解释。

### 6.3 边界（RULES）

- 她的底线、不聊的话题、隐私规则、对他人的边界；
- 与 visibility 配合：`relationship-X` 的私事不会进其他人的对话。

## 9. 自由、安全与预算

| 档位 | 行为 |
|---|---|
| 内部自由 | 文件读写/浏览器/学习/创作，基本不审批 |
| 有边界 | 发帖/发消息/点赞，限速 + 审计；可配置审批 |
| 刹车 | 钱、账号安全、批量外发、删除数据、不可逆操作 → 阻止或强制确认 |
| 预算 | token/时间/并发/磁盘/网络；超限降级 |
| 紧急 | 用户一键停机/禁网/禁发布；她不可绕过 |

## 10. 验收场景（v2 第一轮）

1. **她的一天**：给定一个周末，她起床→看消息→自主活动（整理+写作）→午休→研究→傍晚发一条动态→晚上聊天→写日记/睡眠整理。人能看懂"她今天做了什么"。
2. **被打断**：她正在写作时有人找她 → 依性格/关系决定回/晚回/不回；活动进度保留。
3. **不回复**：给一个高冷人格，连续几条灌水消息 → 她可以不回；重要的人遇到重要的事 → 有保底响应；被问起能解释。
4. **主动**：她完成一个作品/看到有趣的东西 → 主动分享，而不是"在吗"。
5. **隐私**：私密抽屉在网页端不可见；她能主动展示某些内容。
6. **记忆**：和 A 的悄悄话不会出现在和 B 的对话里；人物卡能体现"她对 A 的理解"。
7. **兴趣演化**：多次接触某主题后，她开始主动提起并做相关活动。
8. **失败恢复**：模型失败/活动失败 → 不崩，记录原因，下次重试；工作台产出不丢。

## 11. 开放问题

1. 回复"已读不回"的默认档位怎么定？（建议默认按性格，但"重要关系保底"可配置）
2. 活动期间是否要显示"她在忙/在写东西"给人看（像 AI Town 的状态）？
3. 她是否要"看别人的社交动态"（读 feed）？频率与信息源？
4. 私密抽屉中她愿意主动展示的内容，如何选择（随机/按关系/按内容）？
5. 她的"一天"是否要有时长缩放（现实 24h vs 加速模拟）？
6. 多语言/多时区联系人时，作息以谁为准？
