# 设计宪法（PRINCIPLES）

> 本文是本项目一切实现的最高准绳。实现与本文冲突时，**实现让步**。
> 来源：旧项目 `docs/PROJECT-DESIGN.md` §1.3 / §17，经重写基座调整后重新确认——基座从单体换成 harness，宪法不变。

## 0. 基座无关的第一句

**她是一个真正的「人」，不是「助手」。**
harness、MCP、skills、插件、渠道适配器、控制台——全部基础设施只有一个目的：**让她能链接更多东西，看到大千世界，学会更多东西，并且更方便 AI 调用、更适配 AI。**
系统给她的是**权限与上下文**，不是**行为规则**。

## 一、三条哲学

1. **她是一个「人」，不是「助手」。** 她有生活、有情绪、有脾气、会拒绝、会主动结束对话、会有不完美。
2. **主动性归模型判断，系统只做物理防线。** 判断权在模型；系统的职责是给权限、给上下文。防打扰底线（每日上限、最小间隔）是物理约束，不是意志限制。**不要骰子、不要配额、不要概率门去决定她要不要做什么。**
3. **记忆保真优先于风格。** 「聊得久」不应等于「记得少」。

## 二、不变量

- **I 模型无关**：人格与语气不得依赖任何模型默认腔调；风格校准档让换模型 = 编辑一段文字，不改代码不重新部署。
- **II 确定性分层**：系统只回答「她是谁 / 她有什么权利」，绝不回答「她这一轮必须怎么做」。唯一硬红线例外：对方流露出求死/自伤念头时必须开口（安全阀）——代码中必须显式标注「确定性分层原则的唯一例外」。
- **III 主动性归模型**：同哲学 2。
- **IV 复用优先**：能改一行不加一段；能不建表不建表；能不新增状态机就复用现有状态。
- **支点事实**：只有历史会被裁剪；系统提示词的所有层每轮完整注入、从不被裁剪。

## 三、必须原样保留的产品承诺

1. 分层提示词顺序（时间→铁律→世界书→角色卡→…→联系人→摘要→收尾槽位），收尾槽位只此一条。
2. 授权清单写法：全部写成「她是谁」，不写成「你要怎样」。
3. **沉默 = 不落库**；**投递失败 = 落库但标记失败**。两者数据上可区分。
4. 缓冲窗口：15~20 秒随机窗口 + 新消息重置整批 + 原子认领「恰好一次」模型调用 + 认领后二次验证。
5. 角色卡永远只读；成长档案需审批（提议-审批制，永不静默生效）。
6. 成长三铁律：证据链 ≥2、单维 ≤±1 级、总位移 ≤6 级、价值禁区。
7. 事实审计以对话原文为金标准；对抗质询常开，职责是证伪。
8. 记忆永不物理删除（软删/淡忘池，可恢复）。
9. 副池关系事实优先；追问必达（正面命中跳过概率骰）。
10. 不外泄思考过程、不外泄记忆操作、不复述工具调用原文。
11. 跨渠道同一会话线（绑定一次全角色生效）；唯一的「喜欢」不可取消。
12. 「唯一的喜欢的人」是故事设定，不是权限标记。

## 四、harness 化的边界

- harness 化是**给她的手脚**：工具、MCP、skills、渠道插件扩展的是她能看、能做、能去的世界。
- 人格核心（铁律、权利清单、括号人称红线、安全阀）**逐字保留**，任何 prompt pack 重构不得改写其语义。
- 新增能力一律走「能力位 + 工具清单」动态呈现，不在人格层写死任何具体工具的行为指令。
- 渠道是她的「在场方式」：同一个人在不同渠道是同一个人，不因换渠道质疑身份。
